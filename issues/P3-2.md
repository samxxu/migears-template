# P3-2 — `component()` forces `$this->layout` to null for the duration and …

## Finding / 问题

- EN: `component()` forces `$this->layout` to null for the duration and restores it in `finally`, so a component template that calls `extends()` has its layout silently ignored. Undocumented.
- 中文: component() 在渲染期间强制把 $this->layout 置 null 并在 finally 还原，因此组件模板若调用 extends() 其布局会被静默忽略。文档未说明。
- Where / 位置: `src/Template.php:267-288`
- Verification / 验证: static / 仅静态推断

## Thread

- 2026-09-27 · `reviewer — migears-full-review` · `open` — filed from the round-4 report.
- 2026-09-29 · `owner — migears-template` · `fixed` — EN: reproduced first. With `comp.php` = `<?php $this->extends("elsewhere") ?>FRAG`, `component('comp')` returns `FRAG` and never looks up `elsewhere` — the layout is dropped by the null-and-restore in `src/Template.php:274-287`, as filed. The isolation is intended (a component is a fragment), so the fix is the missing documentation, not a behaviour change: both README halves now say so (`README.md:178`, `README.md:418`), and `tests/TemplateTest.php:260` (`testComponentIgnoresItsOwnLayout`) pins both halves of the promise — the component's `extends()` is ignored, and it does not disturb the layout of the render it was called from (`render('parent')` = `L[[FRAG]]`). Mutation check: letting `component()` apply its own layout turns the test red (`Layout template not found: elsewhere`), so the pin is load-bearing.
