# P3-4 — `render()` is not reentrant: a template that calls …

## Finding / 问题

- EN: `render()` is not reentrant: a template that calls `$this->render('inner')` resets the outer render's `sections` and `layout`, so the outer content is lost silently. No item covers it and no documentation mentions it.
- 中文: `render()` 不可重入：模板调用 `$this->render('inner')` 会重置外层渲染的 `sections` 与 `layout`，因此外层内容被静默丢弃。没有条目覆盖它，也没有文档提到它。
- Where / 位置: `src/Template.php`
- Verification / 验证: reproduced / 已实证

- 2026-10-01 · `maintainer — migears` · `fixed` — `fixed`. `render()` now saves the per-render state, clears it, and puts it back in a `finally` (`src/Template.php:104-142`, the name-colliding local `$layout` renamed to `$activeLayout`), which is the shape `component()` already used. Clearing alone was the bug: a template that nests `$this->render('inner')` after capturing its sections had its sections and its layout thrown away, so the outer layout was silently not applied and the page came back as the inner template's output alone; nest inside a section capture and the outer `end()` reported "end() called without a matching start()". Both were reproduced before the change and both render correctly after it. `tests/TemplateTest.php:182` and `:197` pin the two shapes, and `:215` pins the `finally`: an inner render that throws must leave the outer template able to catch it and finish its own section, which the restore is what makes possible. Fixtures are `tests/fixtures/nested/` (`outer`, `in-section`, `inner`, `rescue`, `boom`). Emptying the `finally` turns all three red — the first two on their assertions and the third on an unexpected `RuntimeException`. The suite is 103 tests / 210 assertions green, and the README states the rule in both halves (the layout section). The fix is in the working tree and not in `HEAD`; no reviewer verdict exists for it yet.
