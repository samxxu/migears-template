## Verdict / 结论

The previous component-state pollution and buffer-leak items are fixed, and template-name traversal is fixed too (NUL, empty segments, `.` and `..` are now rejected). One P1 remains: **`section()` emits unescaped, while default escaping is this module's headline feature**.

上一轮的组件状态污染与缓冲泄漏都修好了，模板名的路径穿越也已修（现在拒绝 NUL、空段、`.`、`..`）。本轮剩一条 P1：**`section()` 是未转义输出，而默认转义是本模块的核心卖点**。

## P1

### P1-1

- **Status / 状态**: Open
- **Where / 位置**: `src/TemplateCompiler.php:56-58`
- **Verification / 验证**: `README.md:78,314` vs `:17`; reproduced
- **EN**: `## section('name') ##` compiles to `<?= $this->section('name') ?>`, that is **unescaped output**, while the README syntax table only says "Output a section" — conflicting with the feature table's "default XSS protection". A section containing `<script>` was emitted verbatim in a layout
- **中文**: `## section('name') ##` 编译为 `<?= $this->section('name') ?>`，即**未转义输出**，而 README 的语法表只写「输出区块」，与特性表「默认 XSS 防护」冲突。实测布局中 section 内含 `<script>` 会原样输出

## P2

### P2-1

- **Status / 状态**: Open
- **Where / 位置**: `src/Template.php:144` vs `:125`
- **Verification / 验证**: reproduced
- **EN**: `raw()` accepts only `string` while `e()` accepts `mixed`, so the two are asymmetric: `### $rows ###` with an array necessarily throws `TypeError`

### P2-2

- **Status / 状态**: Open
- **Where / 位置**: `src/Template.php:133-137`
- **Verification / 验证**: reproduced
- **EN**: A failed `json_encode` is unhandled: `e(["bad" => "\xB1\x31"])` throws `TypeError: htmlspecialchars(): Argument #1 must be of type string, false given` (last round reported "silently drops data"; it is now clearly a TypeError, a change rather than a fix)
- **中文**: `json_encode` 失败未处理：`e(["bad" => "\xB1\x31"])` 抛 `TypeError: htmlspecialchars(): Argument #1 must be of type string, false given`（上一轮报的是「静默丢数据」，现已明确为 TypeError，属变化而非修复）

### P2-3

- **Status / 状态**: Open
- **Where / 位置**: `src/Template.php:177,184-187`
- **Verification / 验证**: static
- **EN**: `end()`'s `$this->sections[$name] = ob_get_clean()` does not check the return value (`string|false`): if a template calls native `ob_end_clean()` between start and end, the stack desynchronises and `section()` returns false while declared `string`
- **中文**: `end()` 的 `$this->sections[$name] = ob_get_clean()` 未检查返回值（`string|false`）；模板若在 start/end 之间调用原生 `ob_end_clean()`，栈失配会让 `section()` 返回 false 而声明为 `string`

### P2-4

- **Status / 状态**: Open
- **Where / 位置**: `src/TemplateCompiler.php:29-38,56-57,64-66`
- **Verification / 验证**: reproduced (compiled artefact)
- **EN**: The compiler splices the section name into a single-quoted string verbatim: `## section("a') . system('id') . ('b") ##` corrupts the compiled artefact; and the escape-mask placeholder `\x00<index>\x00` collides with a genuine NUL+digits+NUL sequence in a template and restores `\##` wrongly
- **中文**: 编译器把 section 名原样插入单引号串，实测 `## section("a') . system('id') . ('b") ##` 会破坏编译产物；转义掩码占位符 `\x00<index>\x00` 与模板中真实 NUL+数字+NUL 冲突时会误还原
